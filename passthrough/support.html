Frequently asked

Why did one file take two seconds and another take five minutes?

Many MKV, MOV and TS files already contain video in a format MP4 can hold directly (H.264 or HEVC). In that case nothing is re-encoded — the content is moved into an MP4 container as-is. That is passthrough: no quality loss, and speed limited only by your disk. Formats MP4 cannot hold (WMV, RMVB, some AVI) genuinely have to be re-encoded, which takes minutes. Each row in the list tells you which path it will take before you start.

CPU and GPU usage stay low. Is it using my hardware?

Yes — and low readings are the sign that it is. On Apple Silicon, video encoding runs on a dedicated Media Engine that is neither the CPU nor the GPU, so it appears in neither graph in Activity Monitor. If the CPU were pegged, that would mean the work had fallen back to slower software encoding.

Why is it asking permission for a folder? (Mac only)

macOS grants a sandboxed app access to the files you select, not to the folders containing them. Saving results next to the source therefore needs one-time permission for that folder. The permission is remembered, and you can clear all saved permissions in the app's settings.

Conversion is slow from my external drive. (Mac only)

If the source is on an external mechanical hard drive and the output is written back to the same drive, the drive head has to move constantly between reading and writing. Measured on one 8 TB USB drive: about 47 MB/s same-drive versus about 182 MB/s writing to the internal disk. Passthrough detects this and offers a one-click switch to the internal disk.

It said the conversion was incomplete and deleted the output.

Passthrough checks every result against the source before saving it. If the length or the track layout does not match what was planned, the job is reported as failed and the partial file is removed. It will never hand you half a file and call it done. The usual cause is a damaged or incompletely downloaded source.

Where did my subtitles go?

Text subtitles (SRT, ASS) are embedded in the MP4. Graphic subtitles (PGS, VobSub) cannot go inside MP4, so they are exported as separate files alongside the video. The row tells you when this has happened.

Where do converted files go on iPad and iPhone? (iPad and iPhone only)

Into the app's own folder, which you can open in the Files app under On My iPad (or On My iPhone) → Passthrough → Converted. To put a result anywhere else — Photos, iCloud Drive, another app — use the share button on the finished row.

Does it need access to my photos or files? (iPad and iPhone only)

No, and it never asks. Both the Files picker and the photo picker run outside the app in their own process, so Passthrough only ever receives the specific items you chose — it has no access to your photo library or your file storage, which is why iOS shows no permission prompt for it.

Can I get the FFmpeg source code?

Yes. Passthrough embeds FFmpeg as dynamically linked LGPL-2.1-or-later libraries. The About window contains the licence text, relinking instructions, a button that reveals the bundled libraries, and the exact corresponding FFmpeg source archive — all included in the app itself.

Reporting a problem

If a file fails to convert, the following makes it far easier to fix:

  • Your device and OS version — Mac model and macOS version, or iPhone/iPad model and iOS version
  • The exact message shown on the failed row
  • The source file's format (the app shows codec and resolution on each row)
  • Which preset you used

Please do not send video files unless asked — most problems can be reproduced from the format description alone.

常见问题

为什么有的文件两秒就完了，有的要五分钟？

很多 MKV、MOV、TS 文件里装的本来就是 MP4 能直接容纳的编码（H.264 或 HEVC）。 这种情况下不需要重新编码，只是把内容原样搬进 MP4 外壳 —— 这就是直通： 画质零损失，速度只受磁盘限制。而 MP4 装不下的编码（WMV、RMVB、部分 AVI） 必须真正重新编码，那才是分钟级的工作。开始之前，任务列表上每一行都会写明走哪条路。

CPU 和 GPU 占用都很低，是没用上硬件吗？

正好相反 —— 占用低恰恰说明用上了。Apple Silicon 上视频编码跑在一块叫 Media Engine 的专用芯片上，它既不是 CPU 也不是 GPU，因此在活动监视器的两条曲线里都不显示。 如果 CPU 被压满，反而意味着退回了慢得多的软件编码。

为什么要我给文件夹授权？（仅 Mac）

macOS 只把你选中的文件的权限交给沙盒 App，不包括文件所在的文件夹。 所以把结果保存到源文件旁边时，需要为那个文件夹授权一次。授权会被记住， 你也可以随时在 App 设置里清除全部已保存的授权。

从外接硬盘转换很慢。（仅 Mac）

如果源文件在外接机械硬盘上，输出又写回同一块盘，磁头要在读写位置之间反复移动。 实测一块 8 TB USB 机械盘：同盘读写约 47 MB/s，写入内置磁盘约 182 MB/s。 Passthrough 会自动识别这种情况，并提供一键切换到内置磁盘。

它说"转换不完整"并把产出删掉了。

Passthrough 在保存之前会拿产出和源文件逐项比对。如果时长或轨道构成与计划不符， 任务判为失败，半成品文件被删除。它绝不会把半截文件当成功交给你。 最常见的原因是源文件本身损坏或没有下载完整。

字幕去哪了？

文本字幕（SRT、ASS）会内嵌进 MP4。图形字幕（PGS、VobSub）MP4 装不下， 会导出为独立文件放在视频旁边。发生这种情况时，任务那一行会写明。

iPad 和 iPhone 上转换好的文件在哪？（仅 iPad 与 iPhone）

在 App 自己的目录里。打开「文件」App，进入我的 iPad（或我的 iPhone） → Passthrough → Converted 即可看到。想把结果放到别处 —— 相册、iCloud 云盘、其他 App —— 用完成那一行上的分享按钮。

它需要访问我的相册或文件吗？（仅 iPad 与 iPhone）

不需要，也从不索取。「文件」选择器和相片选择器都运行在 App 之外的独立进程里， Passthrough 只会收到你选中的那几个项目 —— 它拿不到你的相册，也拿不到你的文件存储， 所以 iOS 不会为它弹出任何权限请求。

能拿到 FFmpeg 的源码吗？

可以。Passthrough 以动态链接方式内嵌 FFmpeg（LGPL-2.1-or-later）。 「关于」窗口里有许可证全文、重新链接说明、一个直接定位到内嵌库的按钮， 以及完全对应的 FFmpeg 源码包 —— 全都随 App 一起分发。

反馈问题

某个文件转换失败时，提供以下信息能让问题好定位得多：

  • 你的设备和系统版本 —— Mac 型号与 macOS 版本，或 iPhone/iPad 型号与 iOS 版本
  • 失败那一行显示的完整提示文字
  • 源文件的格式（App 会在每行显示编码和分辨率）
  • 你用的是哪个转换用途

请不要主动发送视频文件 —— 大多数问题只凭格式描述就能复现。
